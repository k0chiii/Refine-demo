# めいちゃん通知（Slack への送り方）

利用者から 2026-10-28 に渡された仕様（原文のまま）。校正システムの Slack の DM はこの仕様に従い、Slack API を直接呼ばない。校正システム側の作りは `docs/UI_M3E.md` §105 と `docs/DECISIONS.md`（2026-10-28 の行）。

---

## めいちゃん通知

Slack API は直接呼ばない。通知は HTTP で「めいちゃん」（slackbot）に渡し、めいちゃんが Slack へ出す。

ベース URL はデプロイ先であり、ワークスペースではない。五月祭のめいちゃんは次のとおり。末尾スラッシュは付けない。

```text
https://internal.gogatsusai.jp/slackbot/may
```

環境変数名の例は `SLACK_BASE_URL`。未設定なら通知を送らない。

ワークスペースは、リクエスト JSON の `team_id` で指定する。値は Slack のチーム ID で、`T` で始まる。ブラウザ版 Slack の URL `https://app.slack.com/client/Txxxx/Cxxxx` の `Txxxx` がそれである。このプロジェクトはワークスペースとその ID を既に持っているので、新しい ID の置き場は作らない。通知のたびに、そのレコードの ID を `team_id` に入れる。

全通知で共通の `SLACK_TEAM_ID` を1つだけ持つ形にはしない。送り先は呼び出し側が渡す。

リクエストは `Content-Type: application/json` のみ。認証ヘッダは付けない。

## エンドポイント

パスはベース URL に連結する。

### メールからユーザー ID を取る

`POST {SLACK_BASE_URL}/userid`

```json
{ "email": "person@example.com", "team_id": "T0123ABCD" }
```

- 200: `{ "userId": "U...." }`。`userId` が無いときも失敗として扱う。
- 404: そのワークスペースに、そのメールアドレスのメンバーがいない。
- それ以外: 失敗。

メールアドレスは、その `team_id` の Slack プロフィールに登録されているものと一致している必要がある。別ワークスペースの同じ人でも、プロフィールのメールが違えば 404 になる。

### DM

`POST {SLACK_BASE_URL}/dm`

```json
{
  "team_id": "T0123ABCD",
  "user_id": "U0123ABCD",
  "text": "本文",
  "blocks": [],
  "attachments": [],
  "threads": [{ "text": "スレッドの1件目" }]
}
```

`user_id` は直前の `/userid` で取った値を使う。呼び出し側はメールアドレスだけを渡し、ユーザー ID の保存は不要。

`text`、`blocks`、`attachments` のいずれか1つは必須。`blocks` と `attachments` は Slack Block Kit の形。`threads` は任意で、最初の投稿のスレッドに順番にぶら下がる。

200 を成功とする。200 以外は失敗とし、本文はログに残す。

### チャンネル

`POST {SLACK_BASE_URL}/message`

```json
{
  "team_id": "T0123ABCD",
  "channel_id": "C0123ABCD",
  "text": "本文"
}
```

`channel_id` は `C` で始まる。これもそのワークスペースに属するチャンネル ID を、プロジェクトが既に持っている値から渡す。`team_id` と組が違うチャンネルには送らない。本文と `threads` の規則は DM と同じ。

## 送り方

通知1件は次のどちらかである。

- DM: `teamId` と `email` と本文
- チャンネル: `teamId` と `channelId` と本文

`teamId` は必須。未設定のグローバル値で埋めない。渡された ID が、このプロジェクトのワークスペース一覧に無いときは送らず失敗にする。

DM の手順は固定する。

1. `POST /userid` に `email` とその通知の `team_id` を送る。
2. `userId` が取れたときだけ `POST /dm` を、同じ `team_id` で送る。
3. `userId` が取れないときは DM を送らない。エラーログに `team_id` と email を残す。

チャンネルは `POST /message` を1回だけ送る。`/userid` は呼ばない。

同じ処理の中でワークスペースが違えば、通知ごとに `team_id` を変える。1プロセスにつき1ワークスペース、にはしない。

## 開発時

本番と同じ URL へ送るのは、本番相当の起動のときだけにする。それ以外は HTTP を呼ばず、宛先（`teamId`、email または `channelId`）と本文をログに出す。

## 失敗と再送

めいちゃん経由の Slack API にはレート制限がある。短時間に多数送ると届かない。

最小実装は、失敗をログに残してその通知を捨てる。届ける保証が要るなら、通知を保存して一定間隔で少しずつ送る。parrot では 1000ms あたり 1 件をキューから送っている。キューに載せるなら、保存する JSON に `teamId` を含める。送信時に今の設定へ差し替えない。

## やらないこと

- Slack の `chat.postMessage` や Bot Token をこのプロジェクトに置かない。
- ワークスペース ID の新規マスタを作らない。既存レコードの IDを `team_id` に使う。
- URL の `/may` をワークスペース切り替えに使わない。`/may` はめいちゃんの入口で、ワークスペースは `team_id` だけである。

## 確認

1. 持っているワークスペース A の `team_id` と、そのワークスペースにいる人のメールで DM が届く。
2. 同じ人でも、プロフィールのメールが違うワークスペース B の `team_id` では届かず、ログに残る。
3. ワークスペース A のチャンネル ID に、A の `team_id` でチャンネル投稿が届く。
4. 一覧に無い `team_id` では HTTP を呼ばない。
5. 開発起動では HTTP を呼ばず、ログに `teamId` と宛先が出る。

## 校正システムでの読み替え（2026-10-28）

- 校正システムにはワークスペースのレコードが無かったので、管理画面「Slack」でシステム管理者が名前と `team_id` を登録する（利用者指示「ADMIN の管理画面で WS 名と TEAM_ID の登録画面を作る → みんなは設定画面で WS を選ぶだけ」）。仕様の「新規マスタを作らない」はこの点だけ読み替える。
- 各自は「通知の設定」の Slack（DM）の行でワークスペースを選ぶ。送るときはその人が選んだレコードの `team_id` を使う。登録が消えたら送らない。
- チャンネル投稿（`/message`）は使わない。DM だけ。
- 開発環境では `SLACK_BASE_URL` を置かないので HTTP を呼ばない。デモ（ブラウザの中の Convex）は元から外へ送らない。
- レート制限は `@convex-dev/rate-limiter` で DM を 1 秒に 1 件に絞り、超えた分は workpool のやり直しに回す（捨てない）。
- めいちゃんの `/userid` は、見つからないとき 404 でなく 500 と本文 `Failed to get user id` を返している（2026-10-30 に観測）。校正システムはその 500 を「見つからない」と読む。ほかの 5xx・つながらないときはやり直す。引き当てに失敗したときのログには `team_id` とメールアドレスを出す（利用者承認 2026-10-30「出していいので」）。
