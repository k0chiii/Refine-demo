# PWA

要件 T1「最初は Web + PWA」に対応する。ホーム画面・デスクトップにインストールでき、単独のウィンドウで開く。

## できること

| 項目                       | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| インストール               | マニフェスト（`apps/web/public/manifest.webmanifest`）: 名前・`display: standalone`・`start_url` / `scope` は `/`・アイコン 192 / 512 / maskable 512・ショートカット（あなたの担当・制作物・表記ルール）。Chromium 系ではアカウントメニューに「アプリとしてインストール」が出る（`beforeinstallprompt` が来たときだけ）。iOS / iPadOS は Safari の「ホーム画面に追加」（`apple-touch-icon` と standalone 用の meta を用意）                  |
| 速く開く・オフラインで開く | Service Worker がアプリの外枠（index.html・JS・CSS・PDF.js のワーカー・マニフェスト・アイコン）を先にキャッシュする。オフラインでも画面の枠は開き、M3E snackbar で「オフラインです」と知らせる                                                                                                                                                                                                                                               |
| 更新                       | 新しい版が配信されると snackbar に「新しいバージョンがあります ／ 更新」。押したときだけ切り替えて再読み込みする（書きかけの画面を勝手に読み直さない）。開きっぱなしでも 1 時間ごとと画面に戻ったときに確かめる 新しい版の外枠は、前の版のキャッシュにあるハッシュ付きファイル（`/assets/*`）を通信せずに写して用意する（変わったファイルと index.html・マニフェスト・アイコンだけ取り直す。以前は毎回すべて取り直していた。`docs/COST.md`） |
| アイコン                   | Material Symbols「edit_document」をテーマの元色 #1b5fb4 の上に置いたもの。`pnpm pwa:icons` で作り直せる（`apps/web/scripts/pwa-icons.mjs`）                                                                                                                                                                                                                                                                                                  |

## キャッシュの方針（セキュリティ）

非公開の原稿を端末に残さないため、**キャッシュするのは同一オリジンの静的ファイルだけ**。

| 対象                                                                                  | 扱い                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原稿・コメント・通知などのデータ（Convex の WebSocket / HTTP）                        | 横取りしない（キャッシュしない）                                                                                                                                                                                          |
| ファイル取得（Workers の API・R2 の署名付き URL）                                     | 別オリジンなので横取りしない。同一オリジンに置いた場合に備え `/api/`・`/auth/` も素通し                                                                                                                                   |
| 画面の移動（HTML。アプリの画面を開く移動）                                            | キャッシュの index.html をすぐ返す（版ごとの外枠と同じ版の JS・CSS なので揃う。新しい版は待機させ「更新」で切り替え）。キャッシュに無いときだけネットワーク。iframe・拡張子つきのファイル・デモのサイトはネットワーク優先 |
| `/assets/*`（ハッシュ付き）・`/icons/*`                                               | キャッシュ優先。版ごとのキャッシュに入れ、新しい版に切り替わると古い版ごと消す                                                                                                                                            |
| `/pdfjs/*`・`/ocr/*`（PDF.js の文字データ、OCR の学習データ。大きいが版で変わらない） | キャッシュ優先。版をまたいで残す。日本語の PDF に要る文字コード表（cmap）4 本は、アプリが遊びの時間に先に取って残す（最初のページを描く瞬間に取りに行かない）                                                             |
| 日本語フォント（数百の分割ファイル）                                                  | 先読みしない。使ったものだけキャッシュ                                                                                                                                                                                    |

**添付ファイルの端末の写し（Service Worker は関与しない）**: PDF などの添付の本体は、Service Worker ではなく**アプリの画面側のコードが利用者別の Cache Storage**（`mf100-files:<利用者>`）に残す（docs/UI_M3E.md §77）。Service Worker はファイル API を横取りしない（上の表のとおり）。サインアウト・別の利用者のサインイン・認証が切れた画面で消え、期間 14 日・合計 400MB で古い順に消す。機密（restricted）の制作物の添付は残さない（ポリシー値 `persistRestricted`、要件 §12 承認待ち）。開くたびに Worker へ条件付きで尋ね（毎回認可）、見られなければ捨てる。ブラウザの HTTP キャッシュには残さない（Worker は `Cache-Control: private, no-store`）。

オフライン中はデータが届かないので最新の内容は表示されず、保存・提出も完了しない（端末にデータを溜めて後で送る仕組みは作っていない）。

## 実装

- `apps/web/pwa/sw.template.js` … Service Worker 本体。ビルド時に `vite.config.ts` の `pwa()` が、先にキャッシュするファイルの一覧と版（一覧・マニフェスト・本体のハッシュ）を埋め込んで `sw.js` として書き出す（追加の依存なし）
- `apps/web/src/lib/pwa.ts` … 登録・更新の知らせ・オフラインの知らせ・インストール（`useInstallPrompt`）。本番ビルド（デモを含む）だけで登録し、開発サーバーでは登録しない
- `apps/web/public/_headers` … 静的配信（Cloudflare Pages 等）向け。`sw.js`・マニフェスト・index.html は `no-cache`、`/assets/*` は `immutable`、ハッシュの付かない `/pdfjs/*`・`/ocr/*`・`/devices/*` は 30 日、`/icons/*` は 7 日。**他の配信先ではこれと同じキャッシュ指定を設定すること**（`sw.js` が長くキャッシュされると更新が届かない）
- HTTPS が必要（localhost を除く）

## 確認

`pnpm e2e:pwa`（`apps/web/e2e/pwa.mjs`、デモモードのビルドを `vp preview` で配信して実行）:

- マニフェストの必須項目とアイコンの実寸
- Service Worker の登録と画面の制御、外枠のキャッシュ
- キャッシュに入るのが同一オリジンの静的ファイルだけであること
- オフラインの知らせと、オフラインで開き直しても画面が出ること
- 新しい版で「更新」が出て、押すと切り替わり古いキャッシュが消えること

## 2026-10-18 修正: 画面の移動に「リダイレクトを経た外枠」を返していた

- 症状: 本番で「Response served by service worker has redirections」となり、画面（サインインを含む）が開かない。
- 原因: Cloudflare Pages は `/index.html` を `/` へ 308 でリダイレクトする。SW が precache した外枠は「リダイレクトを経た応答」になり、
  画面の移動（navigate）の応答には使えない。キャッシュの外枠をすぐ返すようにした変更（UI_M3E §77）で、毎回この応答を返していた。
- 修正: 外枠を返す前に、リダイレクトを経た応答なら作り直す（`unredirected`）。
  開けない版を入れた端末は「更新」を押せないので、開いているアプリの画面が無いときは新しい版が待たずに切り替わる（画面があるときは従来どおり「更新」を待つ）。
- 確認: `e2e/pwa.mjs` は Pages と同じリダイレクトをする中継を挟んで動かす（修正前は失敗、修正後は成功を確認）。
