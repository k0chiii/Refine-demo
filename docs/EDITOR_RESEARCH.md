## 2. 設計を決めた M3 の規定

| 規定（出典）                                                                                                                                                                      | 当てはめ                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 浮遊ツールバーは本文に関する操作向け。ドッキングは窓の下端だけ。窓端から 16 以上。入らない操作は末尾のオーバーフローメニューへ（Toolbars）                                        | 書式は紙面の上端中央の**浮遊ツールバー**（rounded・standard）。幅が足りないと文字色・インデント、さらに配置・リストを末尾の「その他」へ畳む                  |
| compact では縦ツールバーや複数ツールバーは使わず 1 本に。ドッキングは下端（Toolbars）                                                                                             | compact は**下端のドッキングツールバー**（元に戻す・段落スタイル・太字・斜体・チェックリスト・箇条書き・その他）                                             |
| 浮遊ツールバーの影は、下の内容と区別できるなら外してよい（Toolbars）                                                                                                              | 紙面と重ならない専用の行に置くので影なし。縦の浮遊ツールバー（補助ペインの切替）は影あり                                                                     |
| トグルは連結ボタングループ。複数選択と単一選択がある（Button groups）                                                                                                             | 太字・斜体・下線、リストの 3 種を**連結ボタングループ**に。M3E は既定で単一選択（ラジオ）になるので `multi` を付けて押下状態のトグルにした（a11y で検出）    |
| 選択中のトグルは塗りのアイコン、塗りが無ければ太さで示す（Icon buttons）                                                                                                          | 選択中は面に加え、アイコンを FILL 1・wght 700 に（太字・斜体など塗りの無いアイコンも太さで分かる）                                                           |
| アイコンボタンはホバーで操作名を出す（Icon buttons / Tooltips）                                                                                                                   | すべてのアイコンボタンに M3E のプレーンツールチップ。ショートカットも併記（例: 太字（Ctrl+B））                                                              |
| メニューは一時的な操作に。項目にはキーボード操作を添えられる。条件付きの項目は消さずに無効。web では区切りは divider。サブメニューは大きい画面で。compact はボトムシート（Menus） | 段落スタイル・配置・文字色はラジオ項目のメニュー、ショートカットを末尾に表示。表の編集はサブメニューで、表の外では無効。compact の「その他」はボトムシート   |
| メニュー項目の slot には色見本などを置ける（Menus）                                                                                                                               | 文字色・ハイライトのメニューに色見本                                                                                                                         |
| ダイアログは割り込み。操作は 2 つまで、確定は末尾の端。曖昧な「OK」は避ける（Dialogs）                                                                                            | リンク（キャンセル／適用）、文字カウント（完了）、ショートカット一覧（完了）、競合（あとで／最新を読み込む）。操作は末尾に揃えた（全画面のダイアログに適用） |
| 検索と置換は作業を止めない場所に（Dialogs: ダイアログは使いすぎない／Side sheets: 主の内容を操作する補助）                                                                        | 検索と置換は**補助ペイン**に置き、検索しながら編集を続けられる                                                                                               |
| supporting pane の用途に「文書の編集とコメント」。expanded は横に固定 360、compact / medium は下（Canonical examples › Supporting pane）                                          | 主＝紙面、副＝概要／検索と置換／指摘（412 / 360、ドラッグで幅変更）。839 以下はボトムシート                                                                  |

## 4. 仕組み

- **下書き**: `documentDrafts`（1 制作物に 1 つ）。本文は ProseMirror の JSON、検索・文字数用の平文も持つ。書けるのは版を提出できる人で、制作物が進行中のときだけ。読むのは閲覧権限。版番号による楽観的排他（`version_conflict`）。ドメインは `packages/domain/src/document/DocumentDraft.ts`、ユースケースは `packages/application/src/usecases/documents.ts`、Convex は `apps/convex/convex/documents.ts`。
- **版として提出**: 下書きから HTML を作り、既存の提出ダイアログにファイルとして入れる（アップロード・検証・確定・旧版の受付終了はすべて既存の仕組み）。
- **校正画面**: HTML の添付は書式付きで表示（`RichTextViewer`）。エディタと同じスキーマで読むので、未知の要素やイベント属性は表示されない。範囲指摘は平文の文字オフセット（段落は改行区切り）で保存し、`plainText.ts` の対応表で表示位置に戻す。
- **エディタ基盤**: TipTap 3.31.3（公開から 5 週間以上経った版に固定。`pnpm-workspace.yaml` の overrides で内部依存もそろえた）。
